# استقرار روی Railway (بدون ترمینال)

> این راهنما برای کسی است که ترمینال ندارد. همه‌چیز از طریق وب‌سایت‌ها انجام می‌شود.
> قیمت‌ها و محدودیت‌های Railway را در تاریخ **۱۳ اکتبر ۲۰۲۶** از مستندات رسمی Railway خوانده‌ام؛ ممکن است عوض شود، پس قبل از شروع صفحه‌ی Pricing خودشان را هم ببینید.

## ۰. دو نکته‌ی مهم قبل از شروع

1. **«رایگان» دقیقاً رایگان نیست.** طبق مستندات Railway: حساب Trial یک‌بار ۵ دلار اعتبار می‌دهد و پلن Free ماهانه ۱ دلار اعتبار (۰٫۵ گیگ RAM، ۱ vCPU، حجم Volume برابر ۰٫۵ گیگ). قیمت مصرف: RAM هر گیگ ≈ ۱۰ دلار در ماه، CPU هر vCPU ≈ ۲۰ دلار در ماه.
   تخمین خودم (نه عدد رسمی): ربات بیکار حدود ۱۰۰ تا ۱۵۰ مگابایت RAM می‌گیرد، یعنی تقریباً ۱ تا ۱٫۵ دلار در ماه. پس ممکن است اعتبار ۱ دلاری Free آخر ماه تمام شود و سرویس متوقف شود. با پلن Hobby (۵ دلار در ماه، شامل ۵ دلار مصرف) مشکلی نیست. مصرف واقعی را در بخش **Usage** داشبورد ببینید.
2. **یک Volume لازم است.** بدون Volume، با هر دیپلوی جدید نشست تلگرام، دیتابیس، دسترسی‌های داده‌شده و یادآورها پاک می‌شود. Volume را حتماً روی `/data` وصل کنید.

## ۱. چیزهایی که باید آماده کنید

| چیز | از کجا | برای چه |
| --- | --- | --- |
| `TG_API_ID` و `TG_API_HASH` | <https://my.telegram.org> ← API development tools | اتصال به تلگرام |
| `BOT_TOKEN` | ربات `@BotFather` ← `/newbot` | ربات کنترل (برای دادن دسترسی به دیگران) |
| `MASTER_ADMIN_ID` | ربات `@userinfobot` (عدد ID خودتان) | ادمین اصلی |
| یک رمز طولانی (۱۲+ حرف) | خودتان بسازید | `DASHBOARD_PASSWORD` — از صفحه‌ی ورود محافظت می‌کند |
| یک رمز طولانی دیگر (۱۶+ حرف) | خودتان بسازید | `SESSION_ENCRYPTION_KEY` — نشست را رمزنگاری می‌کند |
| حساب GitHub و حساب Railway | github.com و railway.com | |

## ۲. آپلود کد در GitHub (یک ریپوی **خصوصی**)

1. در GitHub: **New repository** ← نام دلخواه ← **Private** ← Create.
2. فایل zip را روی کامپیوتر از حالت فشرده خارج کنید.
3. در صفحه‌ی ریپو: **Add file ← Upload files** و **محتویات** پوشه (نه خود zip) را بکشید و رها کنید؛ پوشه‌ها (مثل `src`) باید با ساختارشان آپلود شوند. اگر GitHub بیش از ۱۰۰ فایل را قبول نکرد، در دو نوبت آپلود کنید (اول `src`، بعد بقیه).
4. **Commit changes**.

> ریپو را حتماً Private بگذارید. فایل `.env` را هرگز آپلود نکنید؛ رمزها فقط در Railway وارد می‌شوند.

## ۳. ساخت پروژه در Railway

1. **New Project ← Deploy from GitHub repo** و ریپوی خودتان را انتخاب کنید.
2. در تنظیمات سرویس (**Settings**) دو فیلد را اگر خالی بود پر کنید (فایل `railway.json` همین‌ها را خودکار اعمال می‌کند؛ اگر دیدید نادیده گرفته شد، دستی وارد کنید):

   | فیلد | مقدار |
   | --- | --- |
   | **Build Command** | `npm run build` |
   | **Start Command** | `npm start` |

   (Railway خودش وابستگی‌ها را نصب می‌کند؛ نیازی به `npm install` نیست.)
3. **Volume بسازید:** از دکمه‌ی Create (یا راست‌کلیک روی سرویس) ← Volume ← سرویس را انتخاب کنید ← **Mount path: `/data`**.
4. **Variables ← Raw Editor** و این بلوک را (با مقدارهای خودتان) بچسبانید:

   ```
   TG_API_ID=
   TG_API_HASH=
   MASTER_ADMIN_ID=
   BOT_TOKEN=
   DASHBOARD_PASSWORD=
   SESSION_ENCRYPTION_KEY=
   WEB_LOGIN=true
   PORT=8080
   DASHBOARD_ENABLED=false
   ```

   (`DATA_DIR` لازم نیست؛ برنامه خودش از مسیر Volume استفاده می‌کند.)
5. **Settings ← Networking ← Generate Domain** و پورت را `8080` بدهید. (فقط برای ورود اولیه لازم است.)

## ۴. ورود اولیه به تلگرام (از مرورگر)

1. در **Deployments ← Logs** منتظر پیام `WEB_LOGIN setup page is open` بمانید.
2. آدرس دامنه‌ی Railway را با `/setup` در آخرش باز کنید (مثلاً `https://xxxx.up.railway.app/setup`).
3. رمز `DASHBOARD_PASSWORD` را وارد کنید ← شماره‌تان را با کد کشور (مثل `+98912...`) ← کدی که در **اپ تلگرام** برایتان آمد ← و اگر تأیید دومرحله‌ای دارید، رمز آن.
4. با پیام «Signed in» کار تمام است؛ نشست رمزنگاری‌شده روی Volume ذخیره شد و ربات خودکار شروع می‌کند.

## ۵. بعد از ورود موفق

1. **متغیر `WEB_LOGIN` را حذف کنید** (و اگر خواستید دامنه‌ی عمومی را هم Remove کنید). Railway دوباره دیپلوی می‌کند.
2. در تلگرام در Saved Messages بنویسید `.ping`؛ پیام شما باید به `🏓 pong` تبدیل شود.
3. در چت خصوصی با ربات کنترل: `/help`، و برای دادن دسترسی به دیگران: `/grant <ID عددی> self`.

## ۶. هشدارهای ایمنی

- **نشست را فقط روی یک جا اجرا کنید.** اگر همان نشست را هم‌زمان روی کامپیوتر خودتان اجرا کنید، تلگرام خطای `AUTH_KEY_DUPLICATED` می‌دهد و نشست ممکن است باطل شود.
- ورود از IP سرور ممکن است در دستگاه‌های دیگرتان پیام «ورود جدید» بیاورد؛ تأیید کنید که خودتان بودید. بهتر است ورود اولیه همین‌جا (روی Railway) انجام شود، نه جای دیگر.
- فقط اگر لازم است داشبورد را روشن کنید. دامنه‌ی عمومی یعنی هرکسی صفحه‌ی رمز را می‌بیند (با رمز و قفل پس از ۵ تلاش محافظت شده، ولی بی‌دلیل در معرض نگذارید).
- با حساب خودتان و در چارچوب قوانین تلگرام استفاده کنید.

## ۷. عیب‌یابی

| نشانه | علت و راه‌حل |
| --- | --- |
| صفحه‌ی دامنه «Application failed to respond» می‌دهد | `PORT=8080` را در Variables بگذارید و دامنه را با همان پورت بسازید. |
| در لاگ `EACCES` / `permission denied` روی `/data` | متغیر `RAILWAY_RUN_UID=0` را اضافه کنید و دوباره دیپلوی کنید (Volume با دسترسی root وصل می‌شود). |
| بیلد یا اجرا با خطای نسخه‌ی Node (مثلاً `node:sqlite`) | برنامه به Node نسخه‌ی ۲۲٫۱۶ یا بالاتر نیاز دارد (فایل `package.json` همین را اعلام می‌کند). اگر Railway نسخه‌ی پایین‌تری برداشت، متغیر `RAILPACK_NODE_VERSION=22` (یا `24`) را اضافه کنید. |
| «No Telegram session found» | `WEB_LOGIN=true` را بگذارید تا صفحه‌ی ورود دوباره باز شود. |
| «The Telegram session is no longer valid» | نشست باطل شده؛ برنامه آن را کنار گذاشت. `WEB_LOGIN=true` بگذارید و دوباره وارد شوید. |
| بعد از هر دیپلوی همه‌چیز پاک می‌شود | Volume وصل نیست یا Mount path برابر `/data` نیست. |
| صفحه‌ی `/setup` بعد از رمز، روی «Connecting to Telegram…» می‌ماند | اتصال سرور به تلگرام برقرار نشده؛ لاگ را ببینید و چند دقیقه صبر کنید. |
| بیلد دستورهای `railway.json` را نادیده می‌گیرد | (مشکل شناخته‌شده‌ی برخی محیط‌های بیلد) دو دستور بخش ۳ را دستی در Settings وارد کنید. |
| سرویس وسط ماه متوقف شد | اعتبار تمام شده؛ Usage را ببینید یا به Hobby ارتقا دهید. |

صفحه‌ی ورود اگر ۳۰ دقیقه بدون استفاده بماند، خودش بسته می‌شود و سرویس با کد خروج ۰ متوقف می‌شود؛ برای باز کردن دوباره Redeploy کنید.
